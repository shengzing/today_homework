## 1. 概述

### 1.1 目标

用微信原生小程序实现《今日作业》MVP，覆盖 PRD 第 3、4 章的全部功能，与静态原型保持一致的页面结构与交互。

### 1.2 关键约束

| 约束 | 原因 |
|---|---|
| 不引入第三方框架 | 原生开发上线快、包体小；MVP 阶段不引入构建链 |
| 页面不直接调用 `wx.cloud.callFunction` | 统一走 `api.js`，便于加 loading、错误提示、埋点 |
| 排名与积分不在客户端计算 | 服务端权威，避免被篡改（见后端文档第 8 章） |
| 完成按钮点击后**先本地更新、后端确认** | 保证点击到反馈的即时感（乐观更新） |
| 页面栈深度 ≤ 3 | 小程序页面栈上限 10 层，控制使用体验 |

### 1.3 与原型的对应

本仓库的静态原型是本设计的**可交互真相来源**。原型的 `js/screens.js` 与本文档第 6 章一一对应，布局、间距、文案、状态判断均可直接读取原型代码作为实现依据。

## 4. 数据流与状态管理

### 4.1 分层

```
┌──────────────────────────────────────────────┐
│  页面 (Page)                                  │
│   - 只负责渲染与用户交互                       │
│   - 不直接改 store，不直接调云函数             │
└───────────────┬──────────────────────────────┘
                │ this.selectComponent / store
┌───────────────▼──────────────────────────────┐
│  store.js（全局单例）                          │
│   - state: users / classes / assignments /      │
│            completions / achievements          │
│   - actions: 业务动作（含乐观更新）            │
│   - selectors: 派生数据（列表拼装、百分比）     │
└───────────────┬──────────────────────────────┘
                │ await api.xxx()
┌───────────────▼──────────────────────────────┐
│  api.js                                       │
│   - wx.cloud.callFunction 封装                 │
│   - 错误码 → 中文提示映射                      │
│   - 统一 loading / 失败重试                    │
└──────────────────────────────────────────────┘
```

### 4.2 store 结构


### 4.3 派生计算放哪

**放服务端**：完成时间、排名、积分、名次。
**放客户端**：列表拼装、百分比、格式化文案、空态判断。

原型中 `js/store.js` 的实现可作为客户端 `store.js` 的蓝本，但以下方法必须改为接口调用：

| 原型方法 | 改为 |
|---|---|
| `Store.completionsOf()` / `rankingOf()` | `api.getAssignmentRanking()` |
| `Store.achievementOf()` | `api.getAchievement()` |
| `Store.now()` | 服务端时间由接口下发，客户端不再自行取「服务器时间」 |
| `Store.complete()` | `api.completeAssignment()`（含乐观更新） |

> **服务器时间的处理**：小程序本地时间可被用户修改，不可用于排名。客户端不缓存「服务器时间」，而是使用接口返回的 `completedAt`。仅用于展示的「今天 / 昨天」文案，允许使用客户端时间做近似判断。

### 4.4 乐观更新（完成作业）

```js
async function completeAssignment(assignmentId) {
  const local = state.completions[assignmentId] || [];
  if (local.some(c => c.userId === state.user.userId)) return;

  // 1. 立即写入本地，让按钮状态与计数马上变化
  state.completions[assignmentId] = [
    ...local,
    { userId: state.user.userId, completedAt: null, pending: true }
  ];
  patchAssignmentDoneCount(assignmentId, +1);

  try {
    const res = await api.completeAssignment({ assignmentId });
    // 2. 用服务端返回的真实数据替换
    replaceCompletion(assignmentId, res.data.completedAt);
    state.achievements[assignmentId] = null;   // 成就榜需要重新拉取
    return res.data;
  } catch (e) {
    // 3. 失败则回滚
    state.completions[assignmentId] = local;
    patchAssignmentDoneCount(assignmentId, -1);
    throw e;
  }
}
```

**回滚时机**：若云函数 5 秒未响应，回滚并提示「网络异常，请重试」。服务端有唯一约束兜底，重复提交安全。

### 4.5 生命周期与数据刷新

| 页面 | `onLoad` | `onShow` | `onHide` | `onUnload` |
|---|---|---|---|---|
| login | 检查登录态，已登录则 `redirectTo` 首页 | — | — | — |
| home | `loadMyClasses()` | 数据超过 60 秒则刷新 | — | — |
| class | 读路由参数，`loadClass()` + `loadAssignments()` | 若数据过期则刷新 | 关闭 watch | 关闭 watch 与定时器 |
| publish | 按参数决定新建/编辑模式并回填 | — | — | — |
| detail | `loadAssignmentDetail()` | 重新拉取排名 | 关闭 watch | 关闭 watch 与定时器 |
| manage | `loadClass()` + `loadMembers()` | — | — | — |

**过期判定**：模块级记录 `lastFetchAt`，超过 60 秒视为过期。

## 5. API 层封装

```js
// utils/api.js
const ERRORS = {
  '40000': '功能异常，请稍后再试',
  '40001': '填写的内容有误',
  '40100': '微信授权失败，请重新授权',
  '40101': '请先登录',
  '40301': '你不在该班级中',
  '40302': '只有管理员可以执行此操作',
  '40303': '只有发布者可以修改或删除作业',
  '40401': '内容不存在或已被删除',
  '40901': '邀请码不存在或已失效',
  '40902': '你已经是班级成员',
  '50000': '服务异常，请稍后再试'
};

function call(action, payload = {}) {
  return wx.cloud.callFunction({ name: 'api', data: { action, payload } })
    .then(({ result }) => {
      if (!result) throw new Error('EMPTY_RESULT');
      if (result.code === 0) return result.data;
      const err = new Error(result.message || ERRORS[result.code] || '操作失败');
      err.code = result.code;
      err.raw = result.message;
      throw err;
    })
    .catch((e) => {
      if (e.code) throw e;                 // 业务错误，保留原始 code
      const err = new Error('网络异常，请检查网络后重试');
      err.code = 'NETWORK';
      err.origin = e;
      throw err;
    });
}

module.exports = {
  call,
  login: (p) => call('login', p),
  updateNickname: (p) => call('updateNickname', p),
  createClass: (p) => call('createClass', p),
  joinClass: (p) => call('joinClass', p),
  getMyClasses: () => call('getMyClasses'),
  getClassDetail: (p) => call('getClassDetail', p),
  getClassMembers: (p) => call('getClassMembers', p),
  updateClass: (p) => call('updateClass', p),
  removeMember: (p) => call('removeMember', p),
  leaveClass: (p) => call('leaveClass', p),
  transferOwner: (p) => call('transferOwner', p),
  dissolveClass: (p) => call('dissolveClass', p),
  regenerateInviteCode: (p) => call('regenerateInviteCode', p),
  createAssignment: (p) => call('createAssignment', p),
  updateAssignment: (p) => call('updateAssignment', p),
  deleteAssignment: (p) => call('deleteAssignment', p),
  getAssignments: (p) => call('getAssignments', p),
  getAssignmentDetail: (p) => call('getAssignmentDetail', p),
  completeAssignment: (p) => call('completeAssignment', p),
  getCompletionList: (p) => call('getCompletionList', p),
  getAssignmentRanking: (p) => call('getAssignmentRanking', p),
  getAchievement: (p) => call('getAchievement', p)
};
```

**统一错误处理**：在页面的 `catch` 中调用 `toast.error(e)`，由 toast 模块根据 `e.code` 查表输出中文；`40001` 类错误需把消息透传给表单组件标红。

## 6. 页面详细设计

### 6.1 登录页 `pages/login/login`

**入口**：小程序启动时若未登录；`pages/login/login?redirect=xxx` 支持登录后跳回。

**布局**

```
┌─────────────────────────────┐
│           今日作业            │  ← 导航栏（系统）
│                             │
│          ┌────┐             │
│          │ 今 │             │  ← 48×48 圆角 logo，绿色渐变
│          └────┘             │
│        今日作业              │  ← 23px 粗体
│   极简的班级作业工具            │  ← 14px 灰
│   发布 · 一键完成 · 实时排名     │
│                             │
│   ┌───────────────────┐     │
│   │  ⊙ 微信授权登录     │     │  ← 绿色主按钮 48px
│   └───────────────────┘     │
│                             │
│  登录仅使用你的微信昵称与头像    │  ← 底部小字
│  不收集手机号、真实姓名等…      │
└─────────────────────────────┘
```

**交互**

| 元素 | 行为 |
|---|---|
| 微信授权登录 | `wx.getUserProfile` → 拿昵称头像 → `api.login` → `wx.reLaunch` 到首页 |
| 授权取消 | Toast「需要授权才能使用」 |
| 已登录用户进入 | `onLoad` 检测到 `state.user` 存在，直接 `reLaunch` 首页 |

**注意**：`wx.getUserProfile` 在 2021 年后需用户点击触发，且返回的是「微信昵称」而非用户自定义昵称。因此：
- 授权后若拿到空昵称，用「同学」+ 随机数字兜底（如 `同学7823`）
- 用户可在首页头像处随时改成自己的昵称

**头像的时效性问题**：`wx.getUserProfile` 返回的头像 URL 是**临时地址**（带鉴权参数，会过期），不能长期存储。因此：

| 字段 | 存储策略 |
|---|---|
| `avatarUrl` | **不持久化**，仅在本次会话内用于展示，页面刷新后重新获取 |
| `avatarColor` | 持久化。头像拉取失败或未授权时，用色块头像兜底（取昵称哈希映射固定色） |

这样即使微信头像链接过期，界面上也不会出现破图——退化为色块头像，体验不降级。原型里 `Store.avatarColor()` 就是这套逻辑的等价实现。

### 6.3 班级详情页 `pages/class/class`

**路由参数**：`?classId=xxx`；内部用 `data-tab` 记录当前 Tab。

**布局**

```
┌─────────────────────────────┐
│ ‹   三年级二班            ⊙  │  ← ⊙ 打开班级管理
├─────────────────────────────┤
│ [三年] 三年级二班 [管理员] [＋邀请]│
│ 32 名成员                     │
├─────────────────────────────┤
│ 今日作业 3 │ 历史作业 │ 学期成就 │  ← 吸顶
├─────────────────────────────┤
│ [Tab 1] 作业列表                │
│ [Tab 2] 按日期归档的作业列表      │
│ [Tab 3] 学期成就排行            │
└─────────────────────────────┘
```

**Tab 1 / 2 作业卡片**

```
┌─────────────────────────────────┐
│ 11月5日数学作业                   │  ← 16.5px 粗体
│ 完成数学课本第 35 页、第 36 页。      │  ← 13.5px 灰，最多 2 行
│ 🕐 今天 24:00 截止                 │  ← 有截止时间才显示，橙色
├─────────────────────────────────┤
│ 已完成 25 / 32 人          [去完成] │  ← 状态 chip
└─────────────────────────────────┘
```

**卡片元素取舍原则**（与原型一致）：卡片上每个元素要么随作业变化，要么可点击；恒定信息和重复信息一律不留。
- 不显示：发布人（MVP 每班唯一发布人）、发布时间、进度条、状态标签、完成百分比、查看排名链接
- 状态只用底部一个 chip 表达：`去完成`（绿）/ `已完成 ✓`（浅绿）/ `已截止`（灰）

**状态由服务端下发，客户端不做判断**：三个 chip「去完成 / 已完成 ✓ / 已截止」一一对应服务端的 `myStatus` 字段（`'todo' | 'done' | 'expired'`）。客户端**禁止**用本地时间比较 `deadline` 来决定是否「已截止」——用户改手机时间即可伪造。相对时间文案（「3 分钟前完成」）统一用服务端返回的 `serverTime` 校正本地时钟偏差后计算。

**Tab 3 学期成就**

### 8.5 「你是一个诚实的小朋友」提示卡

这是产品的**核心情感反馈**，实现要求：

- 点击「我已完成」**成功后**立即弹出（失败不弹）
- 白色圆角卡片，居中，绿底对勾图标
- 主文案：`你是一个诚实的小朋友`
- 副文案：`本次 +N 分 · 学期成就 M 分 · 班级第 K 名`（逾期时改为「本次逾期完成，不计积分 · 已完成 X 项作业」）
- 2.6 秒后自动消失，可点击穿透（不阻塞操作）

**文案意图**：在同学最可能「想快点按一下刷分」的那一瞬间，用一句肯定代替说教。把得分放在副文案，是让「诚实」和「有回报」同时被看见。

## 11. 异常与边界处理

| 场景 | 处理 |
|---|---|
| 未登录进入任何页 | `wx.reLaunch` 到登录页 |
| 班级已解散 / 被移出 | 接口返回 40301/40401 → toast + 返回首页 |
| 作业已被删除 | 详情页返回 40401 → toast「作业不存在或已删除」+ 返回 |
| 网络异常 | toast「网络异常，请检查网络后重试」，乐观更新回滚 |
| 云函数 5s 超时 | 视为失败并回滚 |
| 重复点击「我已完成」 | 本地先判重；服务端唯一约束兜底，返回既有记录 |
| 邀请码已被作废 | toast「邀请码不存在或已失效」 |
| 转让管理员给自己 | 前端拦截；后端也校验 |
| 最后一个成员退出 | 班级管理员不能直接退出，必须先转让或解散 |
| 完成时作业已被删除 | 后端返回 40401，前端回滚并提示 |
| 排行榜为空 | 空状态「还没有人完成，快来抢第一」 |

### 12.3 单元测试用例清单

#### `utils/format`（时间与文案，客户端唯一容易出错的地方）

| 用例 | 场景 | 期望 |
|---|---|---|
| 相对日期 | 今天 / 昨天 / 明天 / 后天 | `'今天'` / `'昨天'` / `'明天'` / `'后天'` |
| 相对日期 | 3 天后 | 返回绝对日期文案 |
| 截止文案 | 今天 24:00 | `'今天 24:00 截止'` |
| 截止文案 | 无截止时间 | `null` |
| 截止文案 | 已过期 | `'已于 昨天 24:00 截止'` |
| **时区回归** | 服务端 `serverTime` 与本地相差 8 小时 | 相对文案仍以服务端时间为准 |
| 百分比 | 25 / 32 | `78`（四舍五入） |
| 百分比 | 0 / 0 | `0`（不返回 NaN） |

#### `utils/validate`（表单边界，与后端校验保持一致）

| 用例 | 边界 |
|---|---|
| 作业标题 | 空 / 1 字 / 20 字 / 21 字 |
| 作业内容 | 空 / 1 字 / 200 字 / 201 字 |
| 班级名称 | 空 / 1 字 / 20 字 / 21 字 |
| 邀请码 | 少于 6 位 / 6 位 / 含小写 / 含非法字符 |

> 客户端校验只为即时反馈，**服务端仍会重复校验**。两端的字数上限必须由同一份常量驱动（建议把 `config.js` 同时下发到两端）。

#### `store/selectors`（派生计算，与后端算法口径一致）

| 用例 | 场景 | 期望 |
|---|---|---|
| `classStats` | 32 人 / 今日 3 作业 / 完成 63 次 | 完成率 66% |
| `classStats` | 0 作业 | 完成率 0，不返回 NaN |
| `assignmentList` | 今日 / 历史分组 | 按服务端 `dayKey` 分组，不使用本地时间 |
| `myRank` | 已完成且有名次 | 返回名次 |
| `myRank` | 逾期完成 | `rank = null`，状态为逾期 |
| `myRank` | 未完成 | `null` |

#### `store/actions`（乐观更新与回滚，本客户端最易出错的逻辑）

| 用例 | 场景 | 期望 |
|---|---|---|
| 乐观更新 | `completeAssignment` 发起瞬间 | 本地完成记录 +1，按钮立即变为「已完成 ✓」 |
| **回滚** | 接口失败 | 本地完成记录恢复原值，按钮回到「去完成」 |
| **回滚** | 接口超时（5s） | 同上，并 toast「网络异常」 |
| **幂等** | 本地已有完成记录时再次调用 | 直接返回，不发请求 |
| 加载态 | 请求进行中 | 按钮禁用且显示 loading，不可重复点击 |
| 切换班级 | `getMyClasses` 返回新数据 | 旧的班级数据被清空，不残留 |

#### 组件测试

| 组件 | 用例 |

## 14. 原型到小程序的映射

| 原型文件 | 小程序文件 | 备注 |
|---|---|---|
| `js/store.js` | `utils/store.js` + `services/*`（后端） | 拆分：派生计算留客户端，权威计算上移服务端 |
| `js/ui.js` | `utils/toast.js` + `components/confirm-dialog` | `UI.hint` → 「诚实的小朋友」提示卡 |
| `js/screens.js` | `pages/*/index.{js,wxml,wxss}` | 每个 `Screens.xxx` 对应一个页面 |
| `js/app.js`（Actions） | `utils/store.js` 的 actions | 改为调 api.js |
| `css/app.css` | `app.wxss` + `styles/tokens.wxss` | `px` 直接沿用；`:root` 变量改为 `page` 选择器 |

**可直接照抄的部分**：
- 所有布局、文案、间距、圆角、字号（原型已按微信规范设计）
- 三种状态 chip 的判断逻辑（`statusOf`）
- 作业卡片的元素取舍原则
- 「诚实的小朋友」提示卡的文案与结构

**必须重写的部分**：
- 所有 `setTimeout` 模拟的延迟 → 真实的云函数调用与 loading
- `Store.now()` 的固定时间 → 服务端下发的时间
- 排名与积分的计算 → 服务端接口
- `localStorage` 持久化 → 云开发数据库
- `data-action` 的事件委托 → WXML 的 `bindtap` + `data-*` 参数
