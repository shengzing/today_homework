## 1. 概述

### 1.1 目标与范围

后端为「今日作业」小程序提供全部数据能力，覆盖 PRD 第 3 章的全部功能：

- 微信授权登录、昵称维护
- 班级创建、邀请码/二维码加入、成员管理
- 作业发布、修改、删除
- 一键完成、完成记录查询
- 单次作业排名（实时）
- 学期成就积分与排行

**明确不做**（PRD 第 8 章 MVP 边界）：图片/文件上传、作业批改、在线考试、积分商城、多管理员并存、消息推送。

### 1.2 设计原则

| 原则 | 落地方式 |
|---|---|
| 服务端权威 | 完成时间、排名、积分一律由服务端计算，客户端只提交「意图」 |
| 最小权限 | 客户端不直接写任何集合；所有写操作走云函数 |
| 越权即拒绝 | 每个接口先校验班级成员身份，再校验角色，最后校验资源归属 |
| 幂等 | 完成作业等接口可安全重试，重复调用不产生脏数据 |
| 可降级 | 单个非核心能力（实时推送）故障时降级为轮询，不影响主流程 |
| 薄云函数 | 云函数内不写业务分支之外的逻辑，逻辑放 services 层，便于单测 |

### 1.3 技术选型

| 项 | 选型 | 说明 |
|---|---|---|
| 运行时 | Node.js 16.20+ | 与小程序端同生态 |
| 形态 | 微信云开发（CloudBase） | PRD 第 7.1 章建议 |
| 数据库 | 云开发数据库（文档型） | 与小程序端 SDK 天然打通 |
| 身份 | 微信 `openid`（云函数上下文 `cloud.getWXContext()`） | 无需自建账号体系 |
| 实时 | 云开发数据库 `watch` + 轮询兜底 | 见第 7 章 |
| 存储 | 暂不需要独立文件存储 | MVP 不含图片上传 |

### 1.4 规模假设

MVP 阶段按下列规模做容量设计，超出后按第 9 章的路径演进：

- 班级数 ≤ 500，单班级成员 ≤ 100（PRD 不设上限，实际靠班级规模自然约束）
- 单班级单学期作业数 ≤ 60
- 累计完成记录 ≤ 500 万条

## 2. 总体架构

### 2.1 架构图

```
┌──────────────────────────────────────────────────────────────┐
│                       微信小程序（客户端）                      │
│  6 个页面 + 弹层  │  api.js 统一封装  │  store.js 状态层          │
└───────────────┬──────────────────────────────┬───────────────┘
                │ wx.cloud.callFunction        │ db.watch / db.get
                │ （全部写操作 + 敏感读）         │ （仅公开只读集合）
┌───────────────▼──────────────────────────────▼───────────────┐
│                     云函数 api（Node.js）                       │
│  index.js  action 路由 + 统一鉴权 + 统一错误处理                │
│  ├ services/  user / class / assignment / completion / rank   │
│  └ utils/     auth / validate / invite / errcode              │
└───────────────────────────────┬──────────────────────────────┘
                                │ 服务端 SDK（admin 权限）
┌───────────────────────────────▼──────────────────────────────┐
│                    云开发数据库（6 个集合）                      │
│  users / classes / class_members / assignments                 │
│  assignment_completions / assignment_stats                    │
└──────────────────────────────────────────────────────────────┘
```

### 2.2 分层职责

| 层 | 职责 | 不做什么 |
|---|---|---|
| 客户端 store | 缓存、派生计算（百分比、列表拼装）、乐观更新 | 不自行计算排名/积分，不生成时间戳 |
| 客户端 api | 参数组装、错误码转提示 | 不含业务判断 |
| 云函数 index | 路由、鉴权上下文注入、错误包装 | 不写业务逻辑 |
| services | 业务规则、事务、聚合计算 | 不直接接触 HTTP/云调用细节 |
| utils | 纯函数（校验、邀请码、错误码） | 无状态 |

### 2.3 一次请求的完整链路

以「成员点击我已完成」为例：

```
1. 小程序：wx.cloud.callFunction({ name:'api', data:{ action:'completeAssignment', payload:{ assignmentId } } })
2. 云函数 index：
   a. 取出 WXContext → openid → 查 users 找 userId（未注册则拒绝 40101）
   b. 校验入参（assignmentId 非空、类型正确）
   c. 路由到 services/completion.complete()
3. services/completion.complete()：
   a. 查 assignment → 不存在 40401
   b. 查 class_members → 非成员 40301
   c. 查 assignment_completions → 已存在 40901（幂等，直接返回既有记录）
   d. completedAt = new Date()（服务端时间，唯一权威来源）
   e. 写入 assignment_completions
   f. 更新 assignment_stats.doneCount（+1）
4. 返回 { code:0, data:{ completedAt, rank, points, achievementRank } }
5. 小程序：更新本地状态 → 弹出「你是一个诚实的小朋友」提示卡
```

## 3. 数据模型

### 3.1 集合清单

| 集合 | 说明 | 客户端权限 |
|---|---|---|
| `users` | 用户 | 不可读写（全部走云函数） |
| `classes` | 班级 | 仅登录用户可读 |
| `class_members` | 班级成员 | 仅登录用户可读（成员关系本身不敏感） |
| `assignments` | 作业 | 仅登录用户可读 |
| `assignment_completions` | 完成记录 | 仅登录用户可读（实时排行所需） |
| `assignment_stats` | 作业统计快照 | 仅登录用户可读（实时刷新用） |

### 3.2 users

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 用户 ID（服务端生成，非 openid） |
| `openid` | string | 微信用户唯一标识，唯一索引 |
| `nickname` | string | 班级内展示昵称，1–12 字 |
| `avatarUrl` | string | 头像地址（微信头像 URL 或空串） |
| `avatarColor` | string | 头像底色（无头像时用色块头像，十六进制） |
| `createdAt` | date | 创建时间 |

索引：`openid`（唯一）、`createdAt`

### 3.3 classes

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 班级 ID |
| `name` | string | 班级名称，1–20 字 |
| `description` | string | 班级简介，0–40 字 |
| `ownerId` | string | 管理员用户 ID |
| `inviteCode` | string | 邀请码，6 位大写字母数字，唯一索引 |
| `inviteCodeVersion` | number | 邀请码版本号，每次重新生成 +1，用于审计 |
| `status` | string | `active` / `dissolved` |
| `badgeColor` | string | 班级头像底色 |
| `createdAt` | date | 创建时间 |
| `updatedAt` | date | 更新时间 |

索引：`inviteCode`（唯一）、`ownerId`

### 3.4 class_members

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 记录 ID |
| `classId` | string | 班级 ID |
| `userId` | string | 用户 ID |
| `role` | string | `owner` / `member` |
| `joinedAt` | date | 加入时间 |

索引：`classId + userId`（唯一）、`classId`、`userId`

### 3.5 assignments

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 作业 ID |
| `classId` | string | 所属班级 |
| `title` | string | 作业标题，1–20 字 |
| `content` | string | 作业内容，1–200 字 |
| `creatorId` | string | 发布者用户 ID（**改删权限的判定依据**） |
| `deadline` | date | 截止时间，可为 null |
| `status` | string | `published` / `deleted` |
| `createdAt` | date | 发布时间（服务端生成） |
| `updatedAt` | date | 修改时间 |

索引：`classId + createdAt`（倒序，用于列表）、`creatorId`

> **软删除**：删除作业时把 `status` 改为 `deleted` 而不是物理移除。列表查询固定带 `status == 'published'`；完成记录保留，便于后续做统计与审计（PRD 5.3「已产生的历史完成记录不因成员退出班级而删除」的精神延伸）。

### 3.6 assignment_completions

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 记录 ID |
| `assignmentId` | string | 作业 ID |
| `classId` | string | 冗余字段，避免算积分时回查作业所属班级 |
| `userId` | string | 完成者用户 ID |
| `completedAt` | date | **服务端**完成时间，排名唯一依据 |

索引：`assignmentId + userId`（唯一）、`assignmentId + completedAt`、`classId`

### 3.7 assignment_stats

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 与 `assignmentId` 相同 |
| `assignmentId` | string | 作业 ID |
| `classId` | string | 所属班级 |
| `doneCount` | number | 已完成人数 |
| `totalCount` | number | 班级总人数快照 |
| `updatedAt` | date | 更新时间 |

索引：`assignmentId`、`classId`

> **用途**：客户端列表页 watch 这张表即可实时刷新「已完成 x / y 人」，无需重拉整个作业列表。它是 `assignments` 与 `assignment_completions` 的物化视图，由云函数在完成时增量维护。

### 3.8 数据关系

```
users ─┬─< class_members >─┬─ classes
       │                   │
       │                   └─< assignments ─┬─< assignment_completions
       │                                     │
       └─────────────────────────────────────┴─ assignment_stats
```

### 3.9 唯一性约束的实现

云开发数据库的索引**不强制唯一**，唯一性必须由代码保证。约定：

| 约束 | 保证方式 |
|---|---|
| 用户 openid 唯一 | 登录接口内先查后写；并发下用 `openid` 作为 `_id` 直接 upsert |
| 成员不重复加入 | 加入接口先查 `class_members`，已存在直接返回成功（幂等） |
| 同一作业只完成一次 | 完成接口先查 `assignment_completions`，已存在返回既有记录（幂等，code 0） |
| 邀请码唯一 | 生成后循环查重，最多重试 10 次 |

> MVP 并发量小（单班 100 人），先查后写的竞态窗口可接受。若后续并发上升，`assignment_completions` 改为以 `assignmentId + '_' + userId` 作为 `_id`，用主键冲突天然保证唯一。

### 3.10 数据库安全规则

云开发控制台 → 数据库 → 权限设置 → 自定义安全规则：

```jsonc
// users.json
{ "read": false, "write": false }

// classes.json / class_members.json / assignments.json
{ "read": "auth != null", "write": false }

// assignment_completions.json / assignment_stats.json
{ "read": "auth != null", "write": false }
```

**所有集合的客户端写权限一律为 false**。云函数使用服务端 SDK 写入，不受客户端规则限制。

## 4. 云函数设计

### 4.1 目录结构

```
cloudfunctions/
└── api/
    ├── index.js              # 入口：action 路由 + 鉴权 + 错误包装
    ├── config.js             # 常量（字数上限、邀请码字符集、计分规则等）
    ├── package.json
    ├── services/
    │   ├── user.js           # login / updateNickname
    │   ├── class.js          # 班级的 12 个接口
    │   ├── assignment.js     # 作业的 6 个接口
    │   ├── completion.js     # 完成作业 + 完成记录查询
    │   └── rank.js           # 单次排名 + 学期成就
    └── utils/
        ├── auth.js           # getCurrentUser / requireMember / requireOwner
        ├── validate.js       # 入参校验
        ├── invite.js         # 邀请码生成与查重
        └── errcode.js        # 统一错误码
```

> MVP 阶段合并为单个云函数 `api`，冷启动成本共享、维护面小；内部按 services 分层保证可拆分性。用户量上升后可直接拆成 `api-user` / `api-class` / `api-assignment` 三个云函数，接口签名不变。

### 4.2 统一入口

```js
// cloudfunctions/api/index.js
const cloud = require('wx-server-sdk');
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });
const errcode = require('./utils/errcode');
const auth = require('./utils/auth');

const routes = {
  // 用户
  login: require('./services/user').login,
  updateNickname: require('./services/user').updateNickname,
  // 班级
  createClass: require('./services/class').createClass,
  joinClass: require('./services/class').joinClass,
  getMyClasses: require('./services/class').getMyClasses,
  getClassDetail: require('./services/class').getClassDetail,
  getClassMembers: require('./services/class').getClassMembers,
  updateClass: require('./services/class').updateClass,
  removeMember: require('./services/class').removeMember,
  leaveClass: require('./services/class').leaveClass,
  transferOwner: require('./services/class').transferOwner,
  dissolveClass: require('./services/class').dissolveClass,
  regenerateInviteCode: require('./services/class').regenerateInviteCode,
  // 作业
  createAssignment: require('./services/assignment').createAssignment,
  updateAssignment: require('./services/assignment').updateAssignment,
  deleteAssignment: require('./services/assignment').deleteAssignment,
  getAssignments: require('./services/assignment').getAssignments,
  getAssignmentDetail: require('./services/assignment').getAssignmentDetail,
  // 完成与排名
  completeAssignment: require('./services/completion').completeAssignment,
  getCompletionList: require('./services/completion').getCompletionList,
  getAssignmentRanking: require('./services/rank').getAssignmentRanking,
  getAchievement: require('./services/rank').getAchievement
};

exports.main = async (event) => {
  const { action, payload = {} } = event || {};
  const fn = routes[action];
  if (!fn) return errcode.fail('40000', '未知接口');

  try {
    const ctx = await auth.buildContext();   // openid + userId（未注册则抛 40101）
    const data = await fn(payload, ctx);
    return { code: 0, message: 'ok', data };
  } catch (e) {
    if (e && e.bizCode) {
      return errcode.fail(e.bizCode, e.message);
    }
    console.error('[api]', action, e);
    return errcode.fail('50000', '服务异常，请稍后再试');
  }
};
```

### 4.3 鉴权工具

```js
// utils/auth.js
const db = require('./db');

async function buildContext() {
  const { OPENID } = cloud.getWXContext();
  if (!OPENID) throw bizError('40100', '未获取到微信身份');
  const res = await db.collection('users').where({ openid: OPENID }).limit(1).get();
  if (!res.data.length) throw bizError('40101', '请先完成授权登录');
  const user = res.data[0];
  return { openid: OPENID, userId: user._id, nickname: user.nickname };
}

/** 校验是班级成员，返回成员记录 */
async function requireMember(classId, ctx) {
  const res = await db.collection('class_members')
    .where({ classId, userId: ctx.userId }).limit(1).get();
  if (!res.data.length) throw bizError('40301', '你不在该班级中');
  return res.data[0];
}

/** 校验是班级管理员 */
async function requireOwner(classId, ctx) {
  const member = await requireMember(classId, ctx);
  if (member.role !== 'owner') throw bizError('40302', '只有管理员可以执行此操作');
  return member;
}
```

### 4.4 错误码

统一返回体：`{ code: 0, message: 'ok', data: {...} }` 或 `{ code: '40301', message: '你不在该班级中', data: null }`。

| code | HTTP 语义 | 含义 | 客户端处理 |
|---|---|---|---|
| `0` | 200 | 成功 | — |
| `40000` | 400 | 未知接口 | 提示「功能异常」 |
| `40001` | 400 | 参数缺失或非法 | 标红对应表单项 |
| `40100` | 401 | 未获取到微信身份 | 引导重新授权 |
| `40101` | 401 | 未登录 | 跳登录页 |
| `40301` | 403 | 不是班级成员 | Toast 提示并返回 |
| `40302` | 403 | 权限不足（非管理员） | Toast「只有管理员可以…」 |
| `40303` | 403 | 不是该作业的发布者 | Toast「只有发布者可以…」 |
| `40401` | 404 | 资源不存在 | 返回上一页 |
| `40901` | 409 | 邀请码无效或已失效 | Toast |
| `40902` | 409 | 已是班级成员 | 幂等返回成功 |
| `50000` | 500 | 服务异常 | Toast「请稍后再试」 |

> 完成接口的「重复完成」**不算错误**：返回 code 0 + 已存在的记录，保证客户端重试安全。

### 4.5 参数校验

```js
// utils/validate.js
const config = require('../config');

function str(v, { min = 0, max = 999, required = false, name = '字段' } = {}) {
  if (v === undefined || v === null || v === '') {
    if (required) throw bizError('40001', `请填写${name}`);
    return '';
  }
  const s = String(v).trim();
  if (s.length < min || s.length > max) {
    throw bizError('40001', `${name}长度需在 ${min}-${max} 字之间`);
  }
  return s;
}

function id(v, name = 'ID') {
  if (!v || typeof v !== 'string') throw bizError('40001', `缺少${name}`);
  return v;
}
```

## 5. 接口清单

统一调用方式：

```js
wx.cloud.callFunction({ name: 'api', data: { action: 'xxx', payload: {...} } })
```

### 5.1 用户

| action | 入参 | 返回 |
|---|---|---|
| `login` | `{ nickname?, avatarUrl?, avatarColor? }` | `{ userId, nickname, avatarUrl, avatarColor, isNew }` |
| `updateNickname` | `{ nickname }` | `{ nickname }` |

`login` 说明：首次调用创建用户（`openid` 唯一），再次调用仅更新昵称头像（传了才更新）。

### 5.2 班级

| action | 入参 | 返回 | 权限 |
|---|---|---|---|
| `createClass` | `{ name, description? }` | `{ classId, inviteCode }` | 登录用户 |
| `joinClass` | `{ inviteCode }` | `{ classId }` | 登录用户 |
| `getMyClasses` | — | `[{ classId, name, description, role, memberCount, todayCount, todayRate, badgeColor }]` | 登录用户 |
| `getClassDetail` | `{ classId }` | `{ classId, name, description, ownerId, role, memberCount, inviteCode }` | 成员 |
| `getClassMembers` | `{ classId }` | `[{ userId, nickname, avatarUrl, avatarColor, role, joinedAt }]` | 成员 |
| `updateClass` | `{ classId, name?, description? }` | `{ name, description }` | 管理员 |
| `removeMember` | `{ classId, userId }` | — | 管理员，且不能移除自己 |
| `leaveClass` | `{ classId }` | — | 成员；管理员须先转让 |
| `transferOwner` | `{ classId, userId }` | `{ ownerId }` | 管理员 |
| `dissolveClass` | `{ classId }` | — | 管理员 |
| `regenerateInviteCode` | `{ classId }` | `{ inviteCode }` | 管理员 |

`getMyClasses` 返回的 `todayRate`（今日完成率）由服务端聚合计算，客户端不做二次统计。

### 5.3 作业

| action | 入参 | 返回 | 权限 |
|---|---|---|---|
| `createAssignment` | `{ classId, title, content, deadline? }` | `{ assignmentId, createdAt }` | 管理员 |
| `updateAssignment` | `{ assignmentId, title, content, deadline? }` | `{ title, content, deadline, updatedAt }` | **发布者** |
| `deleteAssignment` | `{ assignmentId }` | — | **发布者** |
| `getAssignments` | `{ classId, scope: 'today' \| 'history' }` | `[{ assignmentId, title, content, creatorId, deadline, createdAt, doneCount, totalCount, myCompleted, myCompletedAt }]` | 成员 |
| `getAssignmentDetail` | `{ assignmentId }` | 作业详情 + `{ myCompleted, myCompletedAt, myRank, doneCount, totalCount }` | 成员 |

`updateAssignment` / `deleteAssignment` 的权限判定使用 `assignment.creatorId === ctx.userId`，**不是**班级管理员角色 —— 与 PRD 5.1「管理员可以修改/删除自己发布的作业」一致，且允许未来把发布权限下放给成员时无需改动逻辑。

`updateAssignment` 不修改任何完成记录，已有排名与积分不受影响（PRD 5.1）。

### 5.4 完成与排名

| action | 入参 | 返回 |
|---|---|---|
| `completeAssignment` | `{ assignmentId }` | `{ completedAt, rank, points, achievementRank, achievementPoints, doneCount }` |
| `getCompletionList` | `{ assignmentId }` | `[{ userId, nickname, avatarUrl, completedAt, overdue }]` |
| `getAssignmentRanking` | `{ assignmentId }` | `{ normal: [...], overdue: [...], doneCount, totalCount, myRank }` |
| `getAchievement` | `{ classId }` | `{ rows: [{ userId, nickname, points, done, overdue, rank }], myRow, assignmentCount }` |

`completeAssignment` 返回值同时带上单次名次与学期成就名次，客户端一次调用即可渲染「你是一个诚实的小朋友」提示卡，不需要再发一次请求。

## 6. 核心算法

### 6.1 单次作业排名（PRD 3.7）

```js
async function getAssignmentRanking(assignmentId, ctx) {
  const assignment = await getAssignment(assignmentId);       // 不存在 → 40401
  await requireMember(assignment.classId, ctx);                 // 非成员 → 40301

  const all = await db.collection('assignment_completions')
    .where({ assignmentId }).orderBy('completedAt', 'asc').get();

  const normal = [];
  const overdue = [];
  all.data.forEach(c => {
    const row = {
      userId: c.userId,
      nickname: await nicknameOf(c.userId),
      completedAt: c.completedAt,
      overdue: !!(assignment.deadline && c.completedAt > assignment.deadline)
    };
    (row.overdue ? overdue : normal).push(row);
  });
  normal.forEach((r, i) => { r.rank = i + 1; });

  return {
    normal, overdue,
    doneCount: normal.length + overdue.length,
    totalCount: (await memberCount(assignment.classId)),
    myRank: [...normal, ...overdue].find(r => r.userId === ctx.userId) || null
  };
}
```

规则要点：

1. 以**服务端记录的 completedAt** 升序排序，毫秒精度即为并列时的先后依据
2. 只对已完成的成员排名，未完成成员不出现在名单中
3. `deadline` 之后完成的记录 `overdue = true`，**保留记录但不参与正常排名**，单独成组
4. 同一成员每项作业只可能有一条记录（唯一约束保证）

### 6.2 学期成就积分（原型新增）

**计分规则**：

| 情况 | 单项得分 |
|---|---|
| 作业排名第 1 | 3 分 |
| 作业排名第 2 | 2 分 |
| 作业排名第 3 及以后（已完成） | 各 1 分 |
| 未完成 | 0 分 |
| 逾期完成 | 0 分（完成数仍计入统计） |

```js
function pointsOf(rank) {
  if (!rank) return 0;
  return rank === 1 ? 3 : (rank === 2 ? 2 : 1);
}

async function getAchievement(classId, ctx) {
  await requireMember(classId, ctx);
  const assignments = await publishedAssignments(classId);   // 全部已发布作业（含历史）
  const members = await getMembers(classId);

  const board = new Map();
  members.forEach(m => board.set(m.userId, { ...m, points: 0, done: 0, overdue: 0, total: assignments.length }));

  for (const a of assignments) {
    const { normal, overdue } = await getAssignmentRanking(a._id, ctx);
    normal.forEach(r => {
      const row = board.get(r.userId);
      if (row) { row.points += pointsOf(r.rank); row.done += 1; }
    });
    overdue.forEach(r => {
      const row = board.get(r.userId);
      if (row) { row.done += 1; row.overdue += 1; }   // 逾期完成不计分
    });
  }

  const rows = [...board.values()].sort((a, b) =>
    b.points - a.points || b.done - a.done || (a.userId < b.userId ? -1 : 1)
  );
  rows.forEach((r, i) => { r.rank = i + 1; });
  return { rows, myRow: rows.find(r => r.userId === ctx.userId), assignmentCount: assignments.length };
}
```

**排序规则**：总分 → 完成数 → 用户 ID（保证结果稳定可复现）。

**性能**：32 人 × 6 作业 = 192 条完成记录，单次聚合在毫秒级。若单班级作业数增至数百条，改为：
- 维护 `class_achievement` 汇总集合，完成作业时增量累加
- 或按 `semester` 字段分片统计

**「学期」的口径**：MVP 不做学期划分，学期 = 该班级的全部已发布作业。后续若要真实学期，给 `assignments` 加 `semester` 字段（如 `2026-fall`），聚合时按学期过滤。

const INVITE_CHARS = 'ABCDEFGHJKLMNPQRSTUVWXYZ23456789';  // 去掉易混淆的 I O 0 1

async function generateInviteCode() {

## 7. 实时与同步策略

### 7.1 三层同步

| 场景 | 策略 | 说明 |
|---|---|---|
| 列表页「已完成 x / y 人」 | `db.watch('assignment_stats')` | 云函数在完成时更新 stats，客户端监听后局部刷新数字 |
| 作业详情页排名 | 进入时拉取 + `db.watch('assignment_completions')` | 只监听当前作业的文档范围 |
| 班级成就榜 | 进入时拉取 + 下拉刷新 | 变化频率低，不做实时监听 |

### 7.2 watch 的实现

```js
// 客户端
const watcher = db.collection('assignment_completions')
  .where({ assignmentId: currentId })
  .watch({
    onChange: (snapshot) => { renderRanking(snapshot.docs); },
    onError: (err) => { startPollingFallback(); }   // watch 失败降级
  });
// 页面卸载时
watcher.close();
```

### 7.3 降级策略

`watch` 在部分基础库版本、弱网、或云开发环境异常时不可用。因此所有实时页面都同时具备：

1. 进入页面拉取一次全量
2. `watch` 增量更新
3. 30 秒轮询兜底（三选一，任一可用即可）

页面 `onShow` 时重新拉取，`onHide` 时关闭 watch 与定时器，避免后台耗电。

## 8. 安全设计

PRD 第 7.3 章要求，逐条对应：

| PRD 要求 | 实现 |
|---|---|
| 用户只能访问自己所属班级的数据 | 所有班级相关接口先 `requireMember(classId, ctx)`；`getMyClasses` 只查自己的成员记录 |
| 普通成员不能修改其他成员的完成记录 | 完成记录无任何客户端写入口；`removeMember` 只改成员关系，不动完成记录 |
| 完成时间必须由服务端生成 | `completeAssignment` 内部 `new Date()`，客户端不传时间字段 |
| 排名必须由服务端数据计算 | 排名接口只返回服务端聚合结果，客户端不持有排名原始数据 |
| 邀请码需要具备唯一性 | 生成时循环查重（最多 10 次） |
| 所有操作必须验证班级成员身份 | `requireMember` / `requireOwner` 贯穿所有班级接口 |
| 数据库不能直接向客户端开放不受限制的写入权限 | 所有集合客户端 `write: false`，写操作只走云函数 |

### 8.1 其他安全措施

- **参数校验**：所有入参做类型、长度、枚举校验，拒绝超长字符串与非法字符
- **防越权取数**：作业类接口先查作业、再用其 `classId` 校验成员关系，不信任客户端传的 `classId`
- **注入防护**：云开发为文档型数据库，不存在 SQL 注入；查询条件一律使用参数化 `where`
- **频率限制**：同一用户 1 秒内最多调用 10 次云函数，超出返回 `429`；`completeAssignment` 单独限制为 1 次/秒
- **不返回敏感字段**：`users` 中的 `openid` 不出现在任何对外响应里
- **日志脱敏**：云函数日志不打印 `openid`、完整昵称，只打印 `userId` 后 6 位

### 8.2 「不刷积分」的技术保障

产品层用「你是一个诚实的小朋友」提示引导，技术层保证：

1. 完成记录唯一，重复点击不产生新记录
2. 积分完全由服务端按 `completedAt` 排名计算，客户端无法指定时间
3. 不存在任何「加分」「改分」接口
4. `completeAssignment` 内可追加时间合理性校验（如 `completedAt` 早于 `createdAt` 视为异常，直接拒绝并记日志）

## 9. 性能与容量

### 9.1 预估

| 接口 | 主要开销 | 预估耗时 |
|---|---|---|
| `getMyClasses` | 2 次集合查询 + 1 次聚合 | < 200 ms |
| `getAssignments` | 1 次作业查询 + 1 次完成计数 | < 150 ms |
| `getAssignmentRanking` | 1 次作业 + 1 次完成记录 + N 次昵称查询 | < 300 ms |
| `getAchievement` | M 次排名聚合（M = 作业数） | M=6 → < 500 ms |
| `completeAssignment` | 5 次读写 | < 300 ms |

### 9.2 优化措施

- **昵称批量查询**：`getAssignmentRanking` 中先收集 userId 集合，一次 `_.in()` 查询用户表并建立 Map，避免 N+1
- **统计物化**：`assignment_stats` 避免列表页实时 count
- **聚合缓存**：同一班级的成就榜可在云函数内存中缓存 30 秒（key = classId），用户量上来后再考虑持久化缓存
- **分页**：成员列表超过 100 人时增加 `limit` / `skip`

### 9.3 扩展路径

| 阶段 | 触发条件 | 动作 |
|---|---|---|
| 拆分云函数 | 日调用量 > 5 万 | 拆为 user/class/assignment 三个云函数 |
| 成就榜物化 | 单班作业数 > 100 | 建 `class_achievement` 汇总表，完成时增量更新 |
| 加学期维度 | 产品需要真实学期 | `assignments` 加 `semester` 字段 |
| 多管理员 | 产品需求 | `classes` 加 `admins` 数组，角色判定改为多值 |

## 11. 发布流程

1. **开发**：本地 `miniprogram` 与 `cloudfunctions/api` 联调
2. **自测**：用开发者工具的「云开发 → 云函数 → 本地调试」逐个 action 验证
3. **上传**：`cli cloud functions upload` 上传云函数代码
4. **数据库**：集合与索引在控制台建好，权限规则按 3.10 配置
5. **提审**：小程序版本上传并提交微信审核
6. **灰度**：发布后用 2–3 个真实班级跑 14 天（PRD 第 9 章验证周期），观察完成率与次日留存

**回滚**：云函数保留历史版本，可一键回滚到上一版本；数据库变更一律向前兼容（新增字段允许缺省），不做破坏性变更。
