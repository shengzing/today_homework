# 今日作业 · 微信小程序静态交互原型

依据 `prd.md`（V1.0 MVP）实现的可点击静态原型。纯 HTML/CSS/原生 JS，无构建、无依赖。
**7 个页面**覆盖 PRD 的全部核心流程，每一条业务规则都做成了真实可交互的行为。

---

## 运行

```bash
# 方式一：直接双击 index.html（file:// 协议可用）
open index.html

# 方式二：起一个本地静态服务（推荐）
python3 -m http.server 8899
# 浏览器访问 http://127.0.0.1:8899/index.html
```

页面左侧是**流程说明 + 页面直达 + 演示工具**，右侧是 375×812 的微信小程序机型框。
数据存放在浏览器 `localStorage`，跨天自动重置为初始种子数据。

---

## 文件结构

```
index.html          外层舞台：左侧说明栏 + 右侧设备框 + 弹层宿主
css/app.css         设计系统（tokens / 组件 / 页面样式）
js/store.js         数据层：模拟后端 —— 用户/班级/作业/完成记录 + 业务规则
js/ui.js            组件层：Toast / Dialog / 表单弹窗 / ActionSheet / Loading / 图标 / 伪二维码
js/screens.js       页面层：7 个页面的渲染函数
js/app.js           路由层：页面栈、返回栈、全部交互动作、演示工具
```

分层方式与小程序一致，后续把 `screens.js` 的渲染函数一一对应到 `.wxml`、把
`store.js` 的接口对应到云函数即可迁移。

## 完整操作流程

```
微信授权登录
   └→ 我的班级（首页）
         ├→ 创建班级（弹窗：名称 + 简介）→ 班级详情（成为管理员）
         ├→ 加入班级（弹窗：6 位邀请码）→ 班级详情
         └→ 班级卡片 → 班级详情
                ├→【今日作业】作业卡片（标题 / 内容 / 截止 / 完成人数 / 去完成）
                │      └→ 作业详情
                │           ├→ 内容、截止时间、我的状态
                │           ├→ 完成排行榜（完成率 / 我的名次 / 实时排名 / 逾期分组）
                │           ├→ 我已完成 → 写入服务器时间 → Toast 回报名次
                │           └→ ⋯ 菜单（仅发布者：修改作业 / 删除作业）
                ├→【历史作业】按日期归档 → 作业详情 → 当时的排行榜
                ├→【学期成就】全班学期积分排行 → 我的成绩 + 完整榜单
                ├→ 邀请（班级管理顶部）→ 二维码 / 邀请码 / 分享 / 换新
                ├→ 班级管理 → 改名 / 移除成员 / 转让管理员 / 解散
                └→ 发布作业（仅管理员）→ 发布成功置顶
                        └→ 作业详情 ⋯ → 修改 → 回填表单 → 保存（完成记录与排名不变）
```

### 关键交互设计

| 交互 | 行为 |
|---|---|
| 一键完成 | 按钮进入 loading → 服务端写入完成时间 → 弹出卡片提示「你是一个诚实的小朋友」+ 本次得分与累计成就 → 列表状态、排名同步刷新 |
| 重复完成 | 完成记录唯一索引拦截，提示「你已完成过这项作业」；完成后按钮变为「已完成 ✓ 查看我的排名」 |
| 逾期完成 | 截止后完成 → 二次确认 → 记为「逾期完成」，排行榜底部单独分组，不参与正常排名 |
| 权限差异 | 普通成员看不到「发布作业」按钮；转让管理员后角色实时切换为成员并立即隐藏发布入口 |
| 表单校验 | 标题/内容为空时红框 + 抖动 + 行内错误文案；弹窗表单为空时 Toast 拦截 |
| 截止时间 | 单行选择器，默认「今天 24:00」，可选 今天 / 明天 / 后天 24:00 |
| 移除成员 | 二次确认；移除后成员的历史完成记录仍然保留（符合 PRD 5.3） |
| 修改作业 | 仅发布者可见（详情页头部「修改」或 ⋯ 菜单）；复用发布表单并回填原值；保存后**完成记录与排名不变**（PRD 5.1） |
| 删除作业 | 仅发布者可见；二次确认后从列表与统计中移除，完成记录一并清除，不可恢复 |
| 邀请码失效 | 重新生成后旧码立即失效，页面上原位更新 |
| 实时性 | 左侧「模拟成员完成」可触发他人完成，列表状态与排名实时变化并弹出推送 Toast |
| 学期成就排行 | 班级详情页第三个 Tab：顶部一条「我的成绩」，下方完整榜单（名次 / 头像 / 姓名 / 完成 x 项 / 积分），当前用户行高亮，底部注明计分规则 |
| 空状态 | 无班级 / 无今日作业 / 无历史作业 / 排行榜无人完成，均有独立空状态 |

## 已落地的业务规则

- 完成时间由服务端生成，客户端只提交「完成」信号。
- 每个成员每项作业只能产生一条完成记录（`assignment_id + user_id` 唯一约束）。
- 排名按完成时间升序，未完成成员不参与排名。
- 截止时间之后完成的标记「逾期完成」，保留记录但不参与正常排名。
- 完成记录不可修改、不可撤销。
- 只有班级成员可以完成作业；只有管理员可以发布作业。
- 只有**作业发布者**可以修改 / 删除该作业（用 `creatorId` 判定，不只看班级角色）。
- 管理员退出前需先转让管理员权限（MVP 单管理员）。
- 成员退出 / 被移除后，历史完成记录不删除。
- 邀请码唯一、长期有效，可重新生成使旧码失效。
- 同一用户不可重复加入同一班级。

### 学期成就积分

每个作业按**完成名次**计分，学期累计：

| 名次 | 单项得分 |
|---|---|
| 第 1 名 | 3 分 |
| 第 2 名 | 2 分 |
| 第 3 名及以后（已完成） | 各 1 分 |
| 未完成 | 0 分 |
| 逾期完成 | 0 分（完成数仍计入统计） |

- 位置：**班级详情页的第三个 Tab「学期成就」**，在「历史作业」之后。
- 统计范围：单个班级的全部已发布作业（含历史作业），同学之间才可比。
- 排行榜按 总分 → 完成数 排序，分数相同则并列前面的排名靠前；榜首要展示「我的成绩」，当前用户所在行高亮。
- 每次点击「我已完成」后弹出提示卡「**你是一个诚实的小朋友**」，同时告知本次得分与累计成就 —— 提醒同学不要为了刷积分乱点完成。
- 积分只由服务端根据真实完成时间计算，没有手动加分入口。

## 精简取舍记录（相对第一版）

| 项 | 原方案 | 现在 | 理由 |
|---|---|---|---|
| 截止时间 | 4 个快捷 chip + 自定义面板 | 单行选择器，默认 24:00，只给今天/明天/后天 | 「今天做」心智就是 24 点，多选项是决策负担 |
| 页面数量 | 12 个 | 7 个 | 对齐 PRD「只设计六个主要页面」的预期 |
| 设置昵称 | 独立页面 | 登录页授权即用，首页头像处改名 | 少一次跳转 |
| 创建 / 加入班级 | 独立页面 | 弹窗（2 字段 / 1 字段） | 单字段表单不值得占一整页 |
| 邀请成员 | 独立页面 | 合并进班级管理页邀请卡 | 邀请码 + 二维码只该有一个地方 |
| 我的（个人中心） | 独立页面 | 删除，头像 → 动作面板 | 信息量太少 |
| 作业详情 | 4 张卡（含前三名预览） | 3 张卡，前三名移除 | 排行榜页已有，不重复 |
| 排行榜行 | 每行「完成时间」副标题 | 只在逾期时显示标签 | 右侧已有时间 |
| 班级头部统计行 | 成员 / 作业数 / 完成率 三格 | 整行删除，只留「32 名成员」 | 作业数 Tab 上已有、完成率首页已有 |
| 作业卡片 meta | 发布人 · 日期 · 时间（两行） | `18:15 · 今天 24:00 截止`（一行） | 日期在 Tab 和日期分组标题里已出现过；发布人 MVP 里恒等于管理员 |
| 作业卡片完成度 | `已完成 18/32 人 · 56%` | `已完成 18/32 人` | 进度条已经编码了比例，文字重复 |
| 作业卡片「查看排名」 | 独立文字链接 | 移除 | 卡片底部 4 个元素抢注意力（偏离 PRD 3.5 的字段清单，可按需恢复） |
| 作业卡片发布时间 | `18:15` | 移除 | 「今日」Tab 里日期恒定，历史 Tab 里日期已在分组标题上 |
| 作业卡片进度条 | 计数下方一条进度条 | 移除 | `已完成 18/32 人` 已经表达了同一件事 |
| 作业卡片状态标签 | 顶部「待完成 / 已完成 / 已截止」 | 移除 | 与底部状态 chip 完全重复，每种状态只保留一个信号 |
| 排行榜独立页面 | 一整页 | 内嵌进作业详情页 | 内容与排名在一屏看完，少一次跳转 |
| 实时同步徽标 | 常驻显示 | 移除 | 无实际信息量 |
| 学期成就排行 | 首页顶部卡片 | 班级详情页第三个 Tab | 成就属于班级内部比较，放在班级里才看得到同班同学的位置；首页保持干净 |
| 演示工具 | 4 个 | 2 个 | 够用即可 |

### 卡片信息取舍原则

> 卡片上每个元素，要么**随作业变化**，要么**可点击**；恒定信息和重复信息一律不留。

- 恒定信息（MVP 里每班只有一个发布人）→ 移到作业详情页，卡片不展示。
- 重复信息（完成率出现在首页和班级详情、完成人数与进度条表达同一件事）→ 只保留一处。
- 列表项里"查看排名"这类二级入口 → 收进详情页，保证列表只有**一个主动作**。
- 同一个状态在一张卡片里出现两次（顶部标签 + 底部 chip）→ 只留底部，顶部让位给标题。

## 下一步（转原生小程序）

1. `screens.js` 的每个 `body()` → 对应 `.wxml` + `.wxss`，`action()` → 底部按钮组件。
2. `app.js` 的 `Actions` → 页面方法，`Store` → 云函数调用（`login` / `createClass` / `joinClass` / `createAssignment` / `completeAssignment` / `getAssignmentRanking` …）。
3. 排行榜实时性用云开发数据库 `watch` 监听 `assignment_completions` 集合替代当前的本地刷新。
4. 登录改为 `wx.getUserProfile` 拿昵称头像，数据库按 `openid` 建 `users` 表。
